Number One threads can now start a fresh conversation chapter, clearing model context without losing thread identity or earlier history.

### New

- Start a fresh Number One chapter any time a thread grows too long — earlier chapters stay browsable in chat, and the transition shows a clear "Fresh chapter started" marker.
- HQ Remote (iOS) gains earlier-chapter browsing and controls to start, cancel, or retry a fresh chapter.
- Each agent role — Number One, Director, Milestone Leader, ad-hoc — can now independently pick a Codex model in Settings → Agents. All roles default to GPT-5.6 Sol.
- The ad-hoc agent section now has a right-click menu to spawn a new session or clear inactive sessions.

### Improved

- Tool calls and thinking appear as compact activity rows while a turn runs, then disappear on completion. Full details remain available in the inspector.
- Long responses are now windowed — only the most recent segments show, with a "Show earlier in this response" control. Scrolling up during a live stream freezes the view so content you're reading can't disappear.
- Permissions, launch failures, and uncertain-delivery Retry/Drop controls now live in a persistent banner outside the conversation thread, visible in both live and stopped chat.
- Discussing a "Waiting on you" item while Number One is mid-turn now shows a clear queued hint that clears the instant Number One finishes.
- Follow-up messages to a busy Codex agent are now queued and delivered at the next turn boundary instead of raising a false "needs attention" alert.
- Stopping an agent mid-turn no longer raises a generic attention banner.
- The chat input box now caps at around 160pt tall and scrolls internally.

### Fixed

- Resizing the HQ window with a long draft no longer causes layout jitter.
- Option/Shift+clicking the green zoom button now correctly fills the window to the visible screen area.
- Live chat no longer intermittently shows blank regions where messages should be while a response is streaming.
- Release note drafting no longer fails with large changelogs, and error details now surface clearly when something goes wrong.
